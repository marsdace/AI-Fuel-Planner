# Trail Lab · AI Fuel Planner 技术文档 02 —— FIT 文件解析：数据层

> 面向对象：想研究本程序如何处理 Garmin 数据的开发者。
> 上一篇讲了"为什么需要引擎"，这一篇讲**数据从哪来**：`.fit` 文件是怎么被读懂的，以及解析时要注意的坑。

---

## 一、FIT 是什么

`.fit`（Flexible and Interoperable Data Transfer）是 Garmin 手表的数据格式，为小内存、低功耗手表设计的**二进制协议**。

关键特征：**文件里全是"编号"，没有"名字"**。心率是第几个字节、占几个字节，全靠一本外部字典（Garmin Profile）来解释。

一份 65 分钟、3915 个记录点的实测活动，整份 FIT 只有 **389KB**——比一张手机照片还小。同样的活动，GPX / TCX 要几百 KB 到几 MB。

---

## 二、三段式文件结构

本程序实测文件共 398,762 字节，结构如下：

```
┌─────────────────────────────────────────────┐
│ 文件头  14 字节（Profile 版本 212.01）         │
├─────────────────────────────────────────────┤
│ 数据记录区  398,746 字节                       │
│   定义消息 + 数据消息 交错排列                 │
├─────────────────────────────────────────────┤
│ 文件 CRC-16  2 字节 = 0xA647                  │
└─────────────────────────────────────────────┘
     14 + 398746 + 2 = 398762 字节（校验吻合）
```

- **文件头**：声明"我是 FIT、版本多新、多长"
- **记录区**：正文，定义消息和数据消息交替
- **文件尾 CRC**：整份文件的防伪校验

---

## 三、解析库"看不懂"的真相

用解析库拆一份文件，消息统计可能是这样的：

| 消息 | 数量 |
|------|------|
| record（每秒一个记录点） | 3915 |
| gps_metadata | 3920 |
| **unknown_233（不认识的新消息）** | **3919** |

`unknown_233` 意味着：**手表固件比解析库的字典更新**。它每秒发一条解析库不认识的消息。

> **不是手表没记录，是字典跟不上固件。** 这解释了为什么手表明明记录了很多，程序却只能读出一部分。

本程序在 `utils/fit.js` 中实现了 FIT 解码，并显式处理"未知消息跳过、已知消息精确提取"，不会因为遇到不认识的消息而崩溃。

---

## 四、解析必须注意的坑（写代码时踩过的）

### 4.1 字段缺席是常态

不同手表、不同运动模式，字段集合都不一样。功率计、ClimbPro、心率带——**缺了就降级，不报错**。

代码铁律：**所有字段按"可能为 null"处理**。本程序用 `safeFloat()` 包裹所有数值读取，空值返回 null 而非 0 或 NaN。

### 4.2 无效值 ≠ 0

心率字段的 `0xFF` 表示"未记录"，不是数值 255。如果直接当成 255，心率曲线会凭空多出许多"峰值"。

### 4.3 压缩时间戳头

高频记录用 2 字节压缩时间戳头。自研解析必须实现，否则记录点的时间戳会错乱。

### 4.4 开发者字段

Stryd 功率、CORE 体温等专业硬件数据走自描述消息（developer field）。程序从这里读取第三方设备数据，普通用户可忽略。

### 4.5 最大心率的语义陷阱

**FIT 里 `max_heart_rate` 是"本次运动峰值"，不是你的生理极限。** 把它当最大心率会污染所有心率区间计算。本程序不自动推断最大心率，而是用用户手动输入的 `physiologicalMaxHr`。

---

## 五、从 FIT 提取了什么（本程序的指标）

程序从 `.fit` 提取并汇总以下指标（见 `utils/fit.js` 的 `extractFitMetrics`）：

- **基础数据**：心率（平均/最大/区间）、配速、爬升、下降、时长、距离
- **地形能力**：按坡度分桶（爬升 ≥ +2% / 下降 ≤ −2% / 其余平路）提取平路配速、上坡 VAM、下坡 VAM（`extractTerrainSpeed`）
- **HRV 状态**：注意——普通活动 FIT 文件**不包含 RR 间期或 HRV 状态数据**，需要心率带 + 特定文件。因此 HRV 状态由用户五档手动输入（平衡/不平衡/偏低/极差/无状态）

# Trail Lab · AI Fuel Planner — Web 版（当前正式版）

> 纯 JavaScript 静态 Web 应用：无框架、无构建步骤，可在 `file://` 或任意静态服务器运行。
> 这是 AI Fuel Planner 的**当前正式版本**；早期 Python 测试版见 `../python_legacy/`（已弃用）。

---

## 功能特性

- **五步引导流程**：历史运动 → 用户画像 → 路线参数 → 路线概况图 → 规则引擎 + AI 解释
- **浏览器端解析 Garmin FIT**：通过 Garmin 官方 JS SDK `@garmin/fitsdk`（esm.sh CDN）本地解码，原始数据不上传
- **双语**：中文 / English 一键切换（`app.js` 内 `TEXT.zh` / `TEXT.en`，`state.language` 控制）
- **森林夜空动效背景**：`bg.js`（昼夜循环约 34s，与 `styles.css` 动画同步）
- **AI 仅做解释**：规则引擎负责计算，AI 只负责把结果翻译成人话

## 五步流程详解

| 步骤 | 说明 |
|------|------|
| **1 · 历史运动文件** | 上传 Garmin `.fit` 并「确认并解析」；或点「手动填写用户信息」跳过解析直接进入手动模式 |
| **2 · 用户能力画像** | 确认/调整 HR 五区区间、体重、静息心率、ITRA/UTMB 积分等（可编辑） |
| **3 · 目标路线参数** | 手动填写或「读取目标运动文件」；包含距离、总爬升、天气、官方补给点、**爬升/下降路段 + 阈值** |
| **4 · 路线概况图** | 海拔轮廓 + 补给点分布 + 爬升/下降路段色带，直观确认 |
| **5 · 规则引擎 + AI** | 规则契约 JSON、补给定量输出与 AI 可执行时间轴（Provider 可选 DeepSeek/Gemini/mock） |

## 关键设计：爬升/下降路段 + 阈值

- **整合输入**：步骤 3 中「爬升/下降路段」为单个列表，每行依次按距离位置填写：
  - **类型**：`爬升` / `下降`（下拉）
  - **起点 / 终点**：距起点相对距离 (km)
  - **高差** (m)
- **爬升/下降阈值**（默认 50 m，可改）：只有高差 **≥ 阈值** 的路段才会被算作路段并绘制；低于阈值的视为平坦（不计入爬升合计、不显示色带）
- **海拔曲线单调**：爬升段从起点直线爬升至终点，**终点即该段海拔最高点**；下降段单调下降
- **FIT 自动提取**：读取目标运动文件时，从真实海拔轨迹自动提取爬升/下降路段（按当前阈值过滤，`extractClimbSegmentsFromFit` / `extractDescentSegmentsFromFit`），可再手动修改
- **校验**：所有行需 `起点 < 终点`；有效路段（≥ 阈值）需按序排列且互不重叠、终点不超总距离、爬升高差合计不超总爬升

## 步骤 4 图表说明

- FIT 模式显示目标运动文件**真实海拔轨迹**；手动模式显示**模拟曲线**（基于路段，起点海拔 0）
- 爬坡路段：粉色半透明色带 + `↑高度m`；下降路段：蓝色半透明色带 + `↓高度m`
- 补给点：蓝色标记 + 完整信息卡（名称 / 距离 / D+ / D- / 关门时间），自动避让重叠
- 配色与页面主题统一（深林绿 × 探索橙）；左侧边距自适应，4 位数海拔完整显示

## 文件说明

| 文件 | 职责 |
|------|------|
| `index.html` | 页面结构 + 步骤容器 + 图例；引入脚本/样式（带 `?v=` 版本号用于缓存刷新） |
| `app.js` | 全部逻辑：FIT 解码、画像推导、规则引擎、步骤 3-4 表单与图表渲染、i18n、AI 调用 |
| `styles.css` | 页面样式（深林绿 × 探索橙主题；含步骤 3 网格布局、图表 SVG、动效降级） |
| `bg.js` | 森林夜空动效背景（昼夜循环） |

## 如何运行

```bash
cd web
open index.html                 # 直接打开（推荐现代浏览器）
# 或本地静态服务器（更稳妥，避免 file:// 下 CDN 加载问题）：
python3 -m http.server 8080
# 访问 http://localhost:8080
```

> ⚠️ 若直接双击打开时 FIT SDK（esm.sh）加载失败，请改用本地静态服务器。

## 技术说明

- **FIT 解析**：`https://esm.sh/@garmin/fitsdk`，浏览器端解码（历史运动 + 目标运动两个文件）
- **架构**：`renderEditor(container, fields, values)` 由字段配置数组渲染所有表单；cplist 字段（补给点/路段）以 JSON 字符串存储 `[{key:value}]`
- **i18n**：`TEXT.zh` / `TEXT.en` 字典 + `applyLanguage()`；切换语言会重渲染当前步骤
- **AI**：`callAIPlanner()` 调用所选 Provider；`mock` 返回固定示例，用于离线验证全流程

## 已知限制

- 仅支持越野跑（Trail Running）模式
- 浏览器端 AI 调用可能受 CORS / Provider 安全策略限制，建议先用 `mock` 验证
- `physiological_max_hr` 可选，缺失时给出提示
- 补给点信息仅用于图上标记，不作为绘制海拔曲线的依据
